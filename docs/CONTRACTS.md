# Validex shared contracts

Source of truth for enums, payload shapes and DB tables shared across the team.
Do not change anything here without telling the team. CLAUDE.md wins on conflict.

Machine-readable versions: `docs/schemas/*.json` (generated by
`python -m scripts.export_schemas` from `backend/`) and `docs/api-contract.md`.

## Conventions
- IDs: UUID4 strings.
- Timestamps: UTC, ISO 8601 (`2026-10-26T10:00:00Z`).
- Dates on documents (issue/expiry): ISO date `YYYY-MM-DD`. Expiry checks compare dates only
  and take "today" as an injectable parameter so tests are deterministic.
- bbox: `[x0, y0, x1, y1]` in PDF points, origin top-left, on the given 1-based `page`.
- Everything simulated carries `is_mock: true` or `is_synthetic: true` and is labelled MOCK / SYNTHETIC in UI.

## Application lifecycle
```
draft --submit--> submitted --(officer opens / validation runs)--> under_scrutiny
under_scrutiny --return_for_correction--> returned_for_correction --resubmit--> submitted (version+1)
under_scrutiny --escalate--> escalated --(senior)--> scrutiny_complete | returned_for_correction
under_scrutiny --mark_scrutiny_complete--> scrutiny_complete
```
Each submit/resubmit snapshots the application into `application_versions`.
Documents belong to an application version. Old validation runs are kept.

## Payload shapes

### Finding
```json
{
  "id": "uuid", "application_id": "uuid", "document_id": "uuid|null",
  "validation_run_id": "uuid", "rule_id": "EXP-001", "rule_version": "1",
  "category": "expiry", "severity": "high",
  "title": "Fire NOC has expired",
  "found_value": "2025-03-31", "expected_value": ">= 2026-10-26",
  "evidence": {"page": 1, "bbox": [72, 410, 260, 428], "snippet": "Valid till 31-03-2025"},
  "explanation": "The expiry date on the Fire NOC is before the scrutiny date.",
  "suggested_action": "Upload a currently valid Fire NOC.",
  "status": "open", "visible_to_applicant": true,
  "created_at": "...", "reviewed_by": "uuid|null", "review_reason": "string|null"
}
```
- `document_id` and `evidence` are null when there is no document (e.g. missing document).
- Findings with `category = anomaly` are ALWAYS `visible_to_applicant = false`, enforced in code
  regardless of rule config. Same for review-priority score and cross-application matches.
- Anomaly wording: "preliminary indicator", "requires manual review". Never "forged" / "fraud".

### ExtractedField
```json
{"field_name": "expiry_date", "value": "2025-03-31", "confidence": 0.93,
 "page": 1, "bbox": [72, 410, 260, 428], "source": "pdf_text", "needs_confirmation": false}
```
Standard field names: `institution_name`, `certificate_number`, `issuing_authority`,
`issue_date`, `expiry_date`, `address`, plus doc-type specific ones (documented in extraction service).
Officer corrections set `source = manual`, keep the original value in the audit payload.

### VerificationResult
```json
{"source": "MOCK Fire Services Issuer", "is_mock": true, "reference_submitted": "FNOC-...",
 "requested_at": "...", "status": "mismatch",
 "submitted_values": {"institution_name": "..."}, "source_values": {"institution_name": "..."},
 "mismatches": [{"field": "institution_name", "submitted": "...", "source": "..."}],
 "error": null}
```
Unreachable source / timeout => `status = source_unavailable`, `error` set, and the finding routes to
manual_review. Never invent a result.

### AuditEvent
```json
{"id": 12, "actor": "uuid|system", "event_type": "finding.resolved",
 "target_type": "finding", "target_id": "uuid", "payload": {...},
 "timestamp": "...", "prev_hash": "hex", "hash": "hex"}
```
- `hash = sha256(prev_hash + canonical_json(actor, event_type, target_type, target_id, payload, timestamp))`.
  First event uses `prev_hash = "0" * 64`. Canonical JSON = sorted keys, no spaces.
- Tamper-EVIDENT, not immutable. `GET /api/audit/verify` runs `verify_chain()`.
- Event types use `resource.verb`: `user.login`, `application.created`, `application.submitted`,
  `document.uploaded`, `field.corrected`, `validation.run`, `finding.resolved`, `rules.updated`, ...
- Mask personal fields / IDs in payloads (keep last 4 chars).

### Auth
- `POST /api/auth/login` `{email, password}` -> `{access_token, token_type: "bearer", user}`.
- JWT HS256, claims `sub` (user id), `role`, `exp` (default 8h). Secret from env `JWT_SECRET`.

## Rules and checklists
- Seeded from `backend/config/rules/*.yaml` and `backend/config/checklists/*.yaml` (marked ILLUSTRATIVE).
- Stored as versions in `rule_set_versions`; the rule editor creates a new version, never edits in place.
- Every ValidationRun records `rule_set_version` and `checklist_version`.
- Rule fields: `id, description, category, condition, severity, recommended_action, version, visible_to_applicant`.
- Malformed rules are rejected on load with a clear error.

## Files
- Upload validation: magic bytes (PDF `%PDF`, PNG, JPEG), max 10 MB, allowed types only. SHA-256 stored.
- Files served only via `GET /api/documents/{id}/link` -> signed token valid 5 min -> `GET /api/files/{token}`.
